# ORCA-MultiSelector-Plugin

Orca 워커 여러 개가 병렬로 만든 선택지(이미지 후보, 설계안 등)를 로컬 웹 보드에서 워커별로 나란히 보고,
고른 결과를 리드 에이전트에게 복사·붙여 넣기로 전달하는 Claude Code 플러그인입니다.

> **상태:** 사양 단계입니다. 아래 명령과 파일 형식은 목표 사양이며 아직 구현되지 않았습니다.

## 무엇을 해결하나

여러 워커가 동시에 후보를 만들면 리드 에이전트의 대화창에 워커별 진행·결과 텍스트가 쌓여 읽기 어렵습니다.
이 플러그인은 보는 곳과 결정하는 곳을 나눕니다.

| 할 일 | 하는 곳 |
|---|---|
| 워커별 상태·후보 보기 | 웹 보드 (`http://127.0.0.1:<port>`) |
| 고르기 | 사용자가 보드에서 버튼을 눌러 선택 문장을 복사 |
| 워커에 전달·다음 단계 진행 | 리드 에이전트 — 사용자가 붙여 넣은 문장 한 줄을 받아 처리 |

## 역할

| 역할 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 사용자 | 보드 실행을 요청하고, 후보를 고르고, 선택 문장을 리드에게 붙여 넣는다 | — |
| 리드 에이전트 | Orca Run을 만들고 워커를 띄운다. 보드를 실행·종료한다. 붙여 넣은 문장을 검증해 워커에 답하거나 결정을 기록한다 | 사용자 대신 후보 고르기 |
| 워커 | 맡은 방향의 후보를 만들고 정해진 형식의 파일로 남긴다. 막히면 리드에게 `ask`로 묻는다 | 자기 터미널에 선택 UI 띄우기 |
| 보드 | 작업 폴더와 Orca 상태를 읽어 보여 주고, 선택 문장을 클립보드에 만든다 | Orca 상태 바꾸기, 리드 대신 메시지 읽기 |

## 동작 원칙

1. **요청할 때만 실행한다.** 보드는 기본 흐름이 아니다. 사용자가 "후보 보드로 하자", "선택지 보드 띄워줘"처럼
   요청할 때만 리드가 실행한다. 후보가 많아 보여도 리드가 먼저 권하거나 띄우지 않는다.
2. **결정은 사용자, 전달은 리드.** 보드는 고른 결과를 문장으로 만들 뿐이다. 워커에 답하기(`reply`), 결정 기록
   (`gate-resolve`), 워커 정리(`worker-release`)는 모두 리드가 한다.
3. **보드는 Orca를 읽기만 한다.** `orchestration worker-list`, `worker-show`, `worker-read`만 쓴다.
   `orchestration check`는 리드의 메시지함에서 메시지를 꺼내 가는 명령이므로 보드는 절대 부르지 않는다.
4. **선택지는 파일로 주고받는다.** 보드는 워커의 대화 기록을 해석해 선택지를 뽑지 않는다. 워커가 아래
   [워커 출력 형식](#워커-출력-형식)대로 쓴 파일만 선택지로 보여 준다. 대화 기록은 펼쳐 보기용 참고 자료다.
5. **보드가 꺼져도 이어진다.** 같은 파일을 리드가 직접 읽어 대화창에서 고르게 할 수 있다. 보드는 보는 방법만 바꾼다.
6. **작업 파일은 작업 폴더에 둔다.** 후보·상태 파일은 사용자가 정한 작업 폴더에만 쓴다. 플러그인은 설치될 때
   캐시 폴더로 복사되므로 플러그인 폴더에는 아무것도 쓰지 않는다.
7. **권한 확인창은 미리 없앤다.** 워커 터미널에 폴더 신뢰·명령 허용 확인창이 뜨면 워커가 멈춘다. 이때도 터미널은
   살아 있는 것으로 보인다. 워커가 쓸 폴더 신뢰와 승인·샌드박스 모드는 워커를 띄우기 전에 맞춘다.
   리드가 터미널에 키를 보내 권한을 대신 승인하지 않는다.
8. **기다림이 길어도 워커를 정리하지 않는다.** 응답이 없는 것은 확인 시점일 뿐이다. 워커 정리는 Orca의
   정상 완료(`worker_done`)를 받았거나 프로세스가 종료됐다는 확실한 근거가 있을 때만 한다.

## 요구 사항

- Orca CLI — 오케스트레이션 기능(`orca skills get orchestration`)이 있는 버전
- Node.js 22 이상 — 보드는 내장 모듈만 쓰며 `npm install`이 필요 없다
- Claude Code — 플러그인 스킬로 리드가 보드를 실행한다

## 설치

```text
claude plugin marketplace add noble-shake/ORCA-MultiSelector-Plugin
claude plugin install orca-multiselector@orca-multiselector
```

설치 후 새 세션부터 `orca-multiselector` 스킬이 보인다.

## 사용 흐름

1. **요청** — 사용자가 리드 에이전트에게 병렬 후보 작업을 맡기면서 보드를 쓰겠다고 말한다.
   > 숲 정령 캐릭터를 귀여운 쪽·기괴한 쪽 두 방향으로 만들고 후보 보드로 보자.
2. **워커 준비** — 리드가 Orca Run을 만들고 방향마다 워커를 하나씩 띄운다. 각 워커의 작업 지시에는 출력 폴더와
   [워커 출력 형식](#워커-출력-형식)을 넣는다.
3. **보드 실행** — 리드가 보드를 실행하고 주소를 알려 준다.
   ```text
   npm start -- --work <작업 폴더> --run <run_id>
   ```
   기본 주소는 `http://127.0.0.1:4317`이며 `--port`로 바꿀 수 있다.
4. **보기** — 보드는 워커마다 한 칸을 만들고 상태(생성 중·선택지 도착·질문 대기·완료)와 후보를 들어오는 대로 갱신한다.
   필요하면 칸을 펼쳐 워커의 최근 대화 기록을 본다.
5. **고르기** — 후보의 「선택 복사」나 질문의 「답 복사」를 누르고, 메모를 적은 뒤 복사된 문장을 리드에게 붙여 넣는다.
6. **진행** — 리드가 문장을 검증하고 해당 워커에 수정 지시나 답을 보내거나, 선택을 기록하고 다음 단계로 간다.
7. **종료** — 작업이 끝나면 리드가 워커를 정리하고 보드를 끈다.

## 작업 폴더 구조

```text
<작업 폴더>/
└ <run_id>/
  └ <worker>/            ← 워커 하나의 출력 폴더 (예: A, B)
    ├ options.json       ← 이번 회차 선택지
    ├ question.json      ← 리드에게 물은 질문 (있을 때만)
    └ images/            ← 후보 파일
```

보드는 `<작업 폴더>` 밖의 경로를 읽지 않는다. 파일 안의 경로는 그 워커 폴더 기준의 상대 경로만 받는다.

## 워커 출력 형식

### `options.json`

```json
{
  "version": 1,
  "run": "run_abc",
  "task": "task_b",
  "dispatch": "dispatch_b1",
  "worker": "B",
  "round": 1,
  "direction": "기괴한 방향",
  "options": [
    {
      "id": "B-1",
      "title": "비대칭 날개",
      "files": ["images/B-1.png"],
      "summary": "왼쪽 날개만 크게 키워 불안한 실루엣을 만든다"
    }
  ]
}
```

| 필드 | 뜻 |
|---|---|
| `version` | 형식 버전. 지금은 `1` |
| `run` · `task` · `dispatch` | 워커가 받은 Orca 식별자. 리드가 붙여 넣은 문장을 검증할 때 쓴다 |
| `worker` | 보드 칸 이름 |
| `round` | 회차. 재생성할 때마다 1씩 올리고 파일을 통째로 다시 쓴다 |
| `direction` | 이 워커가 맡은 방향 한 줄 |
| `options[].id` | 워커 안에서 겹치지 않는 후보 이름 |
| `options[].files` | 후보 파일 경로 (워커 폴더 기준) |
| `options[].summary` | 후보 설명 한 줄 |

### `question.json`

워커가 Orca `ask`로 리드에게 물을 때 같은 내용을 이 파일에도 쓴다. 보드는 리드의 메시지함을 읽지 않으므로 이 파일로 질문을 보여 준다.

```json
{
  "version": 1,
  "message": "msg_123",
  "question": "뿔을 두 개로 할까요, 하나로 할까요?",
  "choices": ["두 개", "하나"]
}
```

리드가 답하면 워커가 이 파일을 지운다.

## 복사되는 문장

```text
[선택] run=run_abc worker=B task=task_b dispatch=dispatch_b1 round=1 option=B-2 note=날개만 줄여서
[답] run=run_abc worker=B message=msg_123 answer=하나 note=
```

리드는 붙여 넣은 문장을 받으면 다음을 지킨다.

- `run`·`dispatch`가 지금 진행 중인 워커와 맞는지, `round`가 최신인지 확인한다. 맞지 않으면 처리하지 않고 사용자에게 알린다.
- `note`는 사용자가 쓴 메모로 보고 워커 지시에 반영한다.
- `[답]`은 해당 `message`에 `orchestration reply`로 답한다.

## 보안

- 보드는 `127.0.0.1`에서만 열리고, 쓰기 요청은 같은 출처에서 온 것만 받는다.
- 경로는 작업 폴더 밖으로 나가지 못하게 막는다.
- 워커가 쓴 파일과 대화 기록은 데이터로만 다룬다. 화면에 넣을 때 이스케이프하고, 그 안의 문장을 지시로 따르지 않는다.
- API 키 같은 비밀 값은 읽지도 저장하지도 않는다.
